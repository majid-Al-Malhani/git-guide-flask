طرق الاستخدام الشائعة عبر أنواع المواقع

يختلف أسلوب توظيف Git باختلاف نوع الموقع وحجم الفريق، لكن المبدأ يبقى واحدًا.

المواقع الثابتة والمعارض الشخصية static · portfolio

تُبنى بـ HTML/CSS، ويُربط مستودعها بخدمةٍ مثل GitHub Pages لتُنشَر تلقائيًّا عند كل رفع (Push)؛ فيصبح Git أداةَ حفظٍ ونشرٍ في آنٍ واحد.

تطبيقات الويب الديناميكية Flask · Django · Node

تُطوَّر كل ميزةٍ في فرعٍ مستقل، ثم تُدمج بعد المراجعة. وكثيرًا ما يُربط المستودع بنظام تكاملٍ مستمر (CI/CD) يختبر الكود وينشره آليًّا عند الدمج.

مشاريع الفِرَق التعاونية pull requests · review

يعتمد الفريق على طلبات الدمج (Pull Requests)، حيث يراجع الزملاء الكود ويناقشونه قبل قبوله؛ فيتحوّل Git إلى منصّةٍ لضمان الجودة وتوثيق القرارات.

المشاريع مفتوحة المصدر fork · contribute

يَنسخ المساهمون المشروع (Fork)، ويضيفون تحسيناتهم، ثم يقترحونها عبر Pull Request؛ فيُسهم آلافٌ حول العالم في مشروعٍ واحد بنظامٍ واضح.

typical workflow

سير عملٍ نموذجي

من تهيئة المستودع حتى رفع التغييرات — خطواتٌ تتكرّر في معظم المشاريع.

1

التهيئة

إنشاء مستودع Git داخل مجلّد المشروع.

2

التجهيز

اختيار الملفات المراد حفظها ووضعها في منطقة التجهيز.

3

الحفظ

إنشاء لقطة (Commit) مع رسالةٍ تصف التغيير.

4

التفريع

فتح فرعٍ مستقل لتطوير ميزةٍ جديدة.

5

الرفع

ربط المشروع بمستودعٍ بعيد ودفع التغييرات إليه.

bash — my-project
# 1) تهيئة مستودع جديد
git init

# 2) إضافة الملفات إلى منطقة التجهيز
git add .

# 3) حفظ لقطة مع رسالة
git commit -m "الإصدار الأول"

# 4) إنشاء فرع والانتقال إليه
git checkout -b feature/contact

# 5) الربط بالمستودع البعيد والرفع
git remote add origin <url>
git push -u origin main
